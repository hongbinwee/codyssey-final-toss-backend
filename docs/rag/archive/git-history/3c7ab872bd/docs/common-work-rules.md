# 공통 작업 규칙과 RAG 적용 상태

**기준일:** 2026-10-15
**출처:** 사용자가 이 작업에서 전달한 공통 규칙 요약. 공지·RAG·DB·프론트/백엔드 원문 채널을 별도로 다시 확인한 기록은 아니다.

이 문서는 현재 RAG 작업에서 공통 규칙을 적용하기 위한 작업 메모다. 규칙을 지키는 것과 담당자들이 인터페이스에 합의하는 것은 별개이며, 아래 규격은 담당자 확인 전까지 제안 상태로 다룬다.

## 저장소와 변경 범위

- RAG 실험은 Backend 저장소에서 진행한다.
- 메인 작업은 별도 브랜치에서 진행한다. 이번 작업 브랜치는 `codex/rag-contracts-validation`이다.
- 다른 파트에 영향을 주는 인터페이스나 범위 변경은 관련 담당자와 협의하고 공통 문서에 기록한다.
- 구체적인 브랜치 이름 규칙, 승인 절차, 네이밍·포맷터·커밋 규칙, Python/PostgreSQL 공통 버전은 전달된 규칙에서 확정되지 않았다.

## 데이터와 인터페이스

- 상품의 공통 ID `parent_asin`과 `category`를 보존한다. 리뷰는 상품 ID와 원본 식별자 `review_key`로 연결한다.
- 원본 근거를 검증할 수 있도록 `dataset_version`, 원본 식별자, 필드, 텍스트, 오프셋을 유지한다.
- 공유 샘플에는 필요한 필드만 포함하고, 작성자/사용자 프로필과 이미지·영상 메타데이터는 검색 평가에 필요하지 않으면 제외한다.
- DB → RAG, RAG → Agent, Agent ↔ Backend, Backend ↔ Frontend 계약과 JSON 예시를 각각 준비한다.
- 이 브랜치에서 작성한 DB → RAG 및 RAG → Agent JSON Schema와 예시는 제안안이다. DB·Agent 담당자의 확인은 아직 기록되지 않았다. 나머지 두 경계 계약도 별도 작업이 필요하다.
- RAG 결과에는 공통 상품 ID, 근거 텍스트, 원본 식별자가 포함되어야 한다. `no_results`, `low_relevance`, `error`는 서로 구분한다.

## 누락 데이터와 표현

- 가격이 없으면 미확인/정보 없음으로 둔다. 값을 추정하거나 예산 충족 여부를 만들어내지 않는다.
- 통화를 확인할 수 없으면 환산이나 예산 비교를 하지 않는다.
- 설명이나 리뷰가 없으면 장단점·사양을 사실로 생성하지 않는다.
- 데이터셋의 출처와 기준 시점을 표시한다. 정적 데이터셋 정보를 실시간 가격·재고·배송 정보처럼 나타내지 않는다.
- 검색 근거가 없으면 해당 샘플 범위에서 근거를 찾지 못했다고 표시한다.

## 구현·검증 상태 표기

공유할 때 실제 원본 API 실행, Mock 테스트, 미구현, 미해결을 분리해 기록한다. 명세 작성은 실제 통합 완료로 세지 않는다.

기본 검색은 한 가지 실행 가능한 방식이 필요하다. 현재 사용자가 확정한 기본 방식은 BM25 + FastEmbed 하이브리드, LangChain 연결, RRF 결합이다. BM25와 FastEmbed는 각각 후보를 만들고, 합의된 RRF 설정으로 한 결과 목록을 구성한다. 다른 검색 방식의 비교 실험은 선택 사항이다.

## 이번 작업의 구분

- 실제 원본 API: 샘플 상품·리뷰와 질문의 근거 필드를 읽어 대조한다.
- Mock: 계약 검사, 원본 응답 오류, 중복·누락 페이지, 검색 API 실패 경로의 자동 테스트에 사용한다.
- 미구현/미해결: 실제 BM25·FastEmbed 색인 및 검색 실행, 실서비스 임계값 교정, 공통 질문에 대한 실제 검색 성능, 담당자 합의가 남아 있다.
