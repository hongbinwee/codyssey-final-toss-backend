## 검토 수정과 검증 경계

- 독립 코드 리뷰에서 발견된 원본과 다른 메타데이터(예: 가격·평점) 통과 문제를 수정하고 회귀 테스트를 추가했습니다.
- 페이지 중복 `review_key`로 누락 리뷰를 감출 수 있던 원본 수집 검증을 수정했습니다.
- 검색 HTTP 실패를 실제 시도(`search_executed: true`)로 기록하고 완료된 문항 결과를 보존합니다. 잘못된 JSON 최상위 형식도 예외 추적 없이 실패 보고서에 남깁니다.
- Backend 저장소로 포팅한 계약/출처 테스트 21/21 통과. 예시 JSON 6/6 통과.
- 포팅 후 live API를 다시 조회해 질문 20개 모두의 상품·리뷰 근거를 확인했습니다. 검색 경로 테스트는 MockTransport이며 실제 검색 API POST는 실행하지 않았습니다.
- 공개용 fixture는 평가 질문에 쓰이는 상품 필드와 리뷰만 남겼습니다. 작성자 프로필과 상품/리뷰 미디어는 제외했습니다. 텍스트에서 이메일·전화번호·일반적인 credential 패턴은 0건이며, 원본 연결에 필요한 `review_key` 해시만 남아 있습니다.
- 이전 `toss-ads-project` 체크아웃에서는 기존 테스트 5개를 포함해 총 25개가 통과했습니다. Backend 저장소에는 해당 5개 테스트가 없어 이 브랜치의 수치에 합산하지 않습니다.

## 기존 RAG 초안에서 확인한 실행 문제

이 항목들은 다른 채팅의 파일을 수정하지 않고 확인한 내용입니다.

1. `src/toss_ads/rag/store.py:78,121`에서 `connection.executemany`를 호출합니다. 설치된 Psycopg 3.3.6에는 Connection.executemany가 없고 Cursor.executemany가 있습니다. 현재 코드로 첫 상품/청크 배치를 쓰면 AttributeError가 발생합니다. `with connection.cursor() as cursor: cursor.executemany(...)` 형태로 수정하고 실제 DB 적재 테스트가 필요합니다.
2. `source.py`와 `retriever.py`는 user_id를 최상위에서만 제거합니다. 실제 원본 상품의 `videos[*].user_id`가 남는 것을 확인했습니다. 이번 계약 도구는 원본 정규화 단계에서 재귀 제거하며 해당 동작을 테스트합니다. 기존 RAG 코드에도 통합이 필요합니다.
3. 기존 임계값 0.35는 설정 기본값으로 존재하지만 튜닝 근거가 없습니다. BM25 후보가 있으면 관련성 통과로 처리하는 경로도 있어, 음성 질문 승인 후 false positive를 측정해야 합니다.
4. LangChain FastEmbed 어댑터 사용은 확인됐습니다. 설계에 적힌 Document/BaseRetriever 연결은 코드에서 확인되지 않았습니다.

## 실행 환경 확인

- 현재 확인된 DB에는 RAG 전용 색인 구성이 없습니다. 별도 테스트 환경에 색인을 준비해야 합니다.
- RAG health endpoint는 당시 로컬 검증 환경에서 연결되지 않았습니다. 검색 서비스를 정상 실행했다고 주장하지 않습니다.
- 검색 확장 설치나 컨테이너 이미지 빌드는 실행하지 않았습니다.
