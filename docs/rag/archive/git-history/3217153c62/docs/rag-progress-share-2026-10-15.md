# RAG 작업 진행 현황 — 공유용

**기준일:** 2026-10-15  
**색인 범위:** 전체 원본 30,000개 중 **Appliances(가전제품) 상품 10,000개와 연결 리뷰 65,618개만**  
**대상:** 데이터 전처리·색인(A), 기본 검색·평가(B), 공동 작업(C)

## 현재 상태

이번 범위의 전체 색인과 검색 실행은 완료했습니다. 원본 데이터 전체를 색인한 것은 아니며, 선택한 가전제품 카테고리만 별도 RAG 평가 DB에 적재했습니다.

| 구분 | 상태 | 핵심 근거 |
|---|---:|---|
| A. 데이터 전처리·색인 | **91.7%** (5/6 완료) | 가전제품 10,000개 상품·65,618개 리뷰, 287,105개 근거 청크 색인 |
| B. 기본 검색·평가 | **75.0%** (3/6 완료) | tuning 4문항, holdout 4문항 실행; 관련성/라벨 검토와 검색 품질 개선은 진행 중 |
| C. 공동 작업 | **75.0%** (2/4 완료) | 동일 범위 색인·검색 연결과 실행 문서화 완료; DB/Agent 담당자 최종 합의는 확인 대기 |
| **전체** | **81.25%** (10/16 완료, 6/16 부분 진행) | 완료 100%, 부분 진행 50%로 계산 |

직전 공유본도 체크리스트 가중 진행률은 81.25%였습니다(**변화 0%p**). 이번에는 상태 분류가 바뀐 것이 아니라 실제 실행 범위가 fixture 10개 상품·10개 리뷰에서 가전제품 전체 10,000개 상품·65,618개 리뷰로 확장됐습니다. 검색 평가도 tuning만 있던 상태에서 holdout 4문항까지 실행했습니다.

## 실행 결과

### 색인

- 원본 데이터셋은 세 카테고리 합계 상품 30,000개입니다. 이번 색인에는 **Appliances 10,000개 상품**만 포함했고, 연결된 원본 리뷰 **65,618개**를 적재했습니다.
- 상품 청크 196,882개, 리뷰 청크 90,223개, **전체 근거 청크 287,105개**입니다.
- 리뷰 원본 ID 65,618개 전부 유지, 고아 근거 청크 0개, 격리 상품·리뷰 0개입니다. 색인 범위 테이블에서 Appliances 외 카테고리는 확인되지 않았습니다.
- 별도 볼륨의 localhost 평가 DB에서 실행했습니다. 원본 앱 DB는 읽기 전용으로 사용했고 변경하지 않았습니다.
- 승인된 개인정보 처리 기준(명시적 개인 식별 필드 재귀 제거, 이메일·SSN 형식 마스킹, 강한 연락처 라벨이 붙은 전화번호 형식만 마스킹)을 색인 전에 적용했습니다. 이메일 8건·전화번호 1건을 마스킹했고, 명시적 개인 필드 21,199건을 제거했습니다. 색인 후 상품 payload 10,000행과 근거·원본 메타데이터 각 287,105행 재검사 결과 추가 마스킹 대상은 0건이었습니다.

### 검색 및 평가

| 평가 묶음 | 질문 수 | 상품 적중 | 기대 원본 출처 적중 | 통과 | 잘못된 근거 | 재시도 |
|---|---:|---:|---:|---:|---:|---:|
| Tuning | 4 | 4/4 | 2/4 | 2/4 | 0 | 0 |
| Holdout | 4 | 3/4 | 2/4 | 2/4 | 0 | 1 |
| **합계** | **8** | **7/8** | **4/8** | **4/8** | **0** | **1** |

기대 상품 적중은 87.5%, 기대 원본 출처 적중은 50%입니다. 데이터 근거가 원본과 맞지 않는 사례는 0건이지만, 기대한 정확한 상품 또는 출처를 찾지 못한 질문이 4건 남았습니다. RAG-001/002는 기대 출처 구간이 상위 결과에 없었고, RAG-005는 기대 상품을 찾지 못했으며, RAG-006은 상품은 찾았지만 기대 출처가 없었습니다.

Holdout RAG-008에서 PostgreSQL `InternalError_`(SQLSTATE `XX000`)에 해당하는 `database_failed`가 한 번 발생한 뒤 1회 재시도로 성공했습니다. 원인은 아직 밝혀지지 않았습니다. 따라서 실행 오류 처리가 동작한 사실과 DB 문제가 해결됐다는 주장을 구분합니다.

검색 코드는 BM25 + FastEmbed 하이브리드, LangChain 연결, RRF k=60입니다. 검색 점수 임계값은 정하지 않았습니다. 8개 질문 라벨은 원본 데이터와 대조했지만, 팀 relevance 승인 전이라 평가와 holdout은 **잠정 결과**입니다. 앞선 탐색 실행 후 응답 계약 일관성 수정이 있어 holdout 독립성도 인증하지 않았습니다.

## 남은 작업과 이유

1. **질문 라벨 승인:** 원본 근거 확인 8/8은 끝났지만, 팀의 relevance 판단은 아직 승인되지 않았습니다. 승인 전 점수는 잠정 평가로만 사용합니다.
2. **검색 품질 개선:** RAG-001/002/006의 기대 출처 미적중과 RAG-005의 상품 미적중 원인을 검토하고 tuning에서 다시 확인해야 합니다. 현재 holdout으로 관련성 임계값을 조정하지 않았으며, `RAG_MIN_RRF_SCORE`도 미설정입니다.
3. **오류 원인 조사:** RAG-008의 일시적 `XX000`은 재시도에 성공했지만 원인은 미확인입니다.
4. **공동 규격 확정:** DB 담당자의 배포 DB 확장 설치 위치, Agent 담당자의 응답 필드 수용 여부에 대한 최종 확인 기록이 필요합니다.
5. **원격 반영:** 최신 변경과 실행 문서는 Backend 원격 브랜치에 아직 푸시하지 않았습니다.
