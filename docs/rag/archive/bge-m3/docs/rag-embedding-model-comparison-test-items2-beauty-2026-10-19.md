## 요약

- 평가 대상은 `test_items2`의 `beauty` 범주입니다. 원본의 별도 활성 run에 이미 만들어진 96토큰 청크를 그대로 사용했습니다. 모델 간 검색 비교에서 청킹 차이가 섞이지 않도록 새로 쪼개지는 않았습니다.
- BM25 단독과 현재 MiniLM 구성을 기준선으로 두고, 앞서 비교한 세 대안 E5, BGE-M3, Qwen3를 같은 청크와 질의로 평가했습니다. 대안들은 BM25를 대체한 것이 아니라 BM25 Top 20과 dense 벡터 Top 20을 상품 단위 RRF(`k=60`)로 결합했습니다.
- 현재 수치에서 가장 나은 모델을 확정하기는 어렵습니다. 긍정 질의가 10개이고 기대 상품 목록은 상품명·유형 규칙으로 만든 임시 라벨이며, 사람의 관련성 검수가 없습니다. `Hit@5`가 높아도 확정 정확도로 볼 수 없습니다.
- 전체 질의별 첫 정답 순위와 측정 조건은 아래 표에 기록했습니다. 모델 임베딩 벡터는 임시 디렉터리에만 생성했고 DB에는 쓰지 않았습니다.

## 비교 방법

- 질의마다 활성 run의 `beauty` 데이터에서 가져온 BM25 Top 20을 고정했습니다. 데이터베이스는 읽기만 했습니다.
- E5, BGE-M3, Qwen3는 같은 78,595개 청크를 각각 임베딩하고 dense 벡터 Top 20을 계산했습니다. 기존 MiniLM 결과에는 DB에 저장된 384차원 벡터를 재사용했습니다.
- 각 검색 결과에서 상품별 첫 청크 순위를 취한 뒤 BM25와 dense 결과를 RRF(`k=60`)로 결합했습니다. BM25 단독은 저장된 BM25 청크 순위에서 상품별 첫 순위를 취해 Top 5를 냈습니다.
- 모든 임베딩 모델의 최대 입력 길이는 128 토큰이었습니다. 저장 청크 상한은 96 토큰입니다. E5 문서 입력은 `passage: `, 질의는 `query: ` 접두어를 사용했습니다. Qwen3 질의에는 검색 지시문 템플릿을 붙였습니다.
- 이 평가에는 별도의 리랭커나 답변 생성 모델이 없습니다. BGE-M3는 dense 벡터만 썼고 sparse·multi-vector 기능은 비교하지 않았습니다.

`Hit@1`과 `Hit@5`는 각각 첫 상품 또는 상위 5개 상품 안에 기대 상품이 하나 이상 나온 긍정 질의 비율입니다. 긍정 질의가 10개라 한 질의의 차이가 10%p입니다. `Macro Recall@5`는 기대 상품 중 Top 5에서 찾은 비율을 질의별 계산 후 평균한 값입니다. `Macro MRR@5`는 첫 기대 상품 순위를, `Macro Precision@5`는 Top 5 중 기대 상품 비율을 질의별로 계산해 평균합니다.

검색 결과는 최대 5개이며, 상품 중복을 합친 뒤 후보가 5개보다 적은 질의도 있습니다. 긍정 질의 10개 중 그런 경우는 BM25 6개, MiniLM 0개, E5 1개, BGE-M3 1개, Qwen3 2개였습니다. `Macro Precision@5`는 후보가 적더라도 분모를 5로 계산했습니다.

## 로컬 CPU 비용

문서 임베딩 시간은 78,595개 청크의 벡터를 생성하는 데 걸린 시간이며, 모델 로드 시간·DB 저장·pgvector 인덱스 작성은 포함하지 않습니다. MiniLM 행은 DB에 저장된 벡터를 재사용해 이번 작업의 전체 재임베딩 시간은 측정하지 않았습니다. 질의 임베딩과 exact dense 점수 계산 p50/p95는 12개 질의에서 구한 값입니다.

| --- | --- | --- | --- | --- |
| BM25 단독 | 해당 없음 | 해당 없음 | DB BM25 시간 미계측 | 서비스 DB 측정 미계측 |

MiniLM·E5·Qwen3는 FastEmbed 0.9.0 ONNX CPU 경로(8 threads)를 썼고, BGE-M3는 Transformers CPU `bfloat16` 경로(8 threads)를 썼습니다. 로컬 문서 임베딩 시간은 이 실행 환경의 처리량 지표이지, GPU나 운영 서버 성능을 대표하지 않습니다. Dense 점수 검색은 NumPy 메모리 행렬에서 exact cosine으로 계산했으며, 표의 값은 DB 벡터 인덱스나 API 지연 시간이 아닙니다. BM25 조회의 서비스 지연은 별도로 계측하지 않았습니다.

## 결과 해석

BM25와 임베딩을 결합한 각 행은 동일한 고정 BM25 후보를 포함합니다. 따라서 해당 행의 변화는 임베딩 후보가 RRF에 더해져 상품 순위를 움직인 효과를 반영합니다. Hit@5와 OOD 반환 수치만으로 운영 승자를 정할 수 없고, 정답 라벨을 검수한 더 큰 질의 세트에서 결과를 반복 확인해야 합니다.

운영 후보를 좁힌다면 E5와 BGE-M3를 우선 비교하는 편이 합리적입니다. 둘 다 이번 검색 지표가 BM25 또는 MiniLM 기준선보다 나은지 질의별 표로 확인할 수 있고, E5는 질의 임베딩 시간이 더 짧은 반면 BGE-M3는 문서 임베딩 시간이 이 환경에서 더 짧았습니다. 둘의 실제 품질 차이는 임시 라벨 규모에서 확정할 수 없습니다. Qwen3 결과는 같은 형식으로 표에 포함했으며, 별도의 검색 장점이 있는지 이 질의별 순위와 측정 비용을 함께 봐야 합니다.

## DB와 코드 영향

이번 평가는 `5432/toss_rag`에서 해당 run의 청크·BM25 순위·MiniLM 벡터를 읽고, 대안 임베딩과 최종 RRF 결과를 오프라인으로 계산했습니다. DB 쓰기, DDL, 인덱스 변경은 하지 않았습니다. E5·BGE-M3·Qwen3 문서 벡터는 `/tmp` 아래에만 저장했습니다.

현재 저장된 벡터는 384차원 MiniLM입니다. 1,024차원 모델을 서비스에 적용하면 전체 청크를 선택 모델로 다시 임베딩하고, 새 차원의 DB 컬럼/테이블 및 인덱스와 코드의 차원 검사를 함께 준비해야 합니다. 기존 384차원 벡터와 1,024차원 벡터를 같은 검색 공간에 섞을 수 없습니다. 이 보고서는 DB 마이그레이션이나 운영 API 적용 결과가 아닙니다.

## 결론과 다음 단계

이번 `test_items2/beauty` 비교는 이미 존재하는 96토큰 청크를 이용해 BM25 단독, MiniLM 기준선, 세 대안 임베딩을 같은 검색 흐름으로 평가했습니다. 청킹을 다시 하지 않은 것은 데이터가 이미 별도 run으로 청킹되어 있었고, 모델 차이만 비교하기 위해서입니다.

결과는 라벨 생성 규칙과 10개 긍정 질의에 민감합니다. 먼저 사람이 기대 상품과 OOD 질의를 검수한 뒤 재평가하고, 그 결과를 보고 임베딩 후보를 선택하는 것이 타당합니다. 이전 데이터셋 결과는 [기존 `test_items/beauty` 비교 문서](rag-embedding-model-comparison-test-items-beauty-2026-10-19.md)에 있습니다.
